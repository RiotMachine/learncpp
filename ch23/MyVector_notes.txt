std::unique_ptr
  assignment first cleans up current object
  destructor cleans up current object

  type and scalar/array are what matter
      std::unique_ptr<T[]> can be pointed to an array of any size

  std::move(uni_ptr) convert a unique_ptr to an R-value for move semantics 
      use only if we're done with uni_ptr parameter

  .swap(uni_ptr) swaps two std::unique_ptrs
  .reset(ptr) is used to pass a raw pointer to a std::unique_ptr
      why use this over assignment?
  .release() returns the raw pointer to object
      unassigns the unique_ptr, does not clean up object


std::copy_n
    takes src start iterator, count, and dest start iterator
    copies count number of objects from src to dest


std::move
    static cast's object to r-value reference
    if object does not have move semantics, copy semantics still work if def
        fundamental types fall into this boat
    algorithm
        takes src start iterator, src end iterator, and dest start iterator
        uses std::move() on each object in the container
        uses range [start, end)
